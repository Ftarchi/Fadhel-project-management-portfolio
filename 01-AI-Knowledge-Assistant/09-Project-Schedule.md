# Project Schedule

The AI Knowledge Assistant MVP will be delivered within an 8-week project timeframe.

The schedule uses a hybrid delivery approach, with activities running in parallel where dependencies allow, while maintaining required security and quality gates before pilot deployment.

## 8-Week Project Schedule

| Week | Planned Activities |
|---|---|
| **Week 1** | Key stakeholder meetings; clarify requirements, scope, security and access needs |
| **Week 2** | Prepare and validate knowledge sources; continue security and access design |
| **Week 3** | Start development/configuration; begin testing where functionality is ready |
| **Week 4** | Continue development and testing; begin pilot preparation |
| **Week 5** | Functional, accuracy, integration and security testing |
| **Week 6** | Remediation and retesting; finalize security validation, pilot readiness and onboarding |
| **Week 7** | Controlled pilot deployment and monitoring |
| **Week 8** | Pilot evaluation, KPI review, lessons learned and MVP presentation |

## Key Dependencies

The following dependencies are considered critical to successful pilot deployment:

- Requirements must be sufficiently defined before development can progress.
- Approved knowledge sources are required for reliable AI responses.
- Security and access controls must be designed and validated before pilot deployment.
- Development must provide sufficient functionality before final testing can be completed.
- Testing must be completed before pilot readiness can be confirmed.
- Any identified high-severity security vulnerabilities must be remediated and successfully retested before pilot deployment.
- Pilot readiness activities must be completed before the controlled pilot launch.

## Parallel Activities

Where dependencies allow, activities will be performed in parallel to protect the 8-week timeline.

Examples include:

- Knowledge-source preparation and security/access design.
- Development and testing of completed functionality.
- Testing and pilot preparation.

## Critical Path

The initial critical path is:

**Requirements → Development → Testing → Remediation/Retesting → Security Validation → Pilot Readiness → Pilot Launch**

The critical path will be monitored throughout the project because changes to activity durations, dependencies, scope or risks may affect the planned pilot date.

## Schedule Management

The project manager will monitor progress against the baseline schedule and assess the impact of delays or changes on the critical path, project objectives and pilot date.

Schedule recovery options may include sequencing activities in parallel, reducing MVP scope, or adjusting the pilot date, subject to stakeholder approval and without compromising required security and quality controls.
